# INT335: Design Thinking
## Unit 4: Product Design and Prototyping (Quick Revision Guide)

---

### 1. Key Concept Overview
* **Prototype**: A tangible, testable simulation or artifact created to answer specific questions, test hypotheses, and fail cheaply before production.
* **Prototyping Philosophy**: *"Build to think, test to learn."* Separate ego from the artifact.
* **Core Rule**: Test the **riskiest assumptions** first (e.g., willingness to use/trust before visual polish).

---

### 2. Prototype Fidelity Comparison
| Dimension | Low-Fidelity (Lo-Fi) | High-Fidelity (Hi-Fi) |
| :--- | :--- | :--- |
| **Form** | Paper sketches, cardboard, wireframes | Clickable mockups, coded prototypes, 3D prints |
| **Speed & Cost** | Extremely fast and negligible cost | Slower, resource-intensive |
| **Primary Goal** | Test structural layout, concepts, and user flow | Test usability details, interactions, visual UI |
| **User Feedback** | Honest, conceptual feedback | Focuses on cosmetic and fine-grained UI details |

---

### 3. Paper Prototyping & Storyboarding
* **Paper Prototyping**:
  * Simulating screen workflows using paper cards, sticky notes, and cutouts.
  * *Roles*: User (acts on paper), "Computer/Facilitator" (swaps screens), Observer (notes errors silently).
* **Storyboarding**:
  * Comic-strip style sequential visualization of user experience over time.
  * *Key Elements*: User persona, trigger/context, action, interface interaction, emotional state, and resolution.

---

### 4. Wireframing Principles & UI Conventions
* **Wireframe**: A grayscale structural blueprint of a screen defining content hierarchy, UI controls, and layout.
* **Visual Restraint**: Use grayscale and basic typography to avoid premature debates on color/branding.
* **Standard Control Conventions**:
  * *Radio Buttons*: Select exactly **one** option from a mutually exclusive list.
  * *Checkboxes*: Select **multiple** independent options.
  * *Toggle Switches*: Immediate on/off binary setting.
  * *Buttons*: Trigger an action/submission.
* **Screen States**: Always design for default, empty, loading, error, and success states.

---

### 5. User Flows & Flowchart Conventions
* **User Flow**: A step-by-step path a user follows to complete a target task.
* **Standard Flowchart Symbols**:
  * *Oval (Terminator)*: Start / End of process.
  * *Rectangle*: Screen, Step, or User Action.
  * *Diamond*: Decision point (conditional branches: Yes/No).
  * *Arrow*: Directional flow.

---

### 6. Minimum Viable Product (MVP)
* **Definition (Eric Ries)**: The simplest version of a product that allows a team to collect the maximum amount of validated learning about customers with the least effort.
* **Key Characteristic**: Must deliver a complete, coherent slice of end-to-end value (not a half-built car, but a functional skateboard).
* **Types of MVPs**:
  * *Landing Page MVP*: Validates market demand and click-through interest before building.
  * *Concierge MVP*: Delivers the service manually behind the scenes to learn user behavior.
  * *Piecemeal MVP*: Assembles existing off-the-shelf tools into a working prototype.
