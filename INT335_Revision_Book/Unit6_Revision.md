# INT335: Design Thinking
## Unit 6: Innovation Project, Re-Design and Product Presentation (Quick Revision Guide)

---

### 1. Key Concept Overview
* **Innovation Process**: Iterative refinement connecting user research, design development, engineering feasibility, and persuasive communication.
* **The Refinement Cycle**:
  $$\text{Define Assumption} \rightarrow \text{Build Prototype} \rightarrow \text{Test with Users} \rightarrow \text{Record Evidence} \rightarrow \text{Refactor/Re-design}$$

---

### 2. Iteration, Refactoring & Strategic Pivoting
* **Incremental Iteration**: Small, localized design improvements (e.g., resizing touch targets, rewriting error text).
* **Design Refactoring**: Improving internal consistency, code modularity, UI component systems, or mechanical parts without altering core functionality.
* **Product Re-Design**: Fundamental structural overhaul triggered by invalidated problem definitions, architectural flaws, or major usability failures.
* **Strategic Pivot**: Changing a core pillar of the business/product model (e.g., target customer segment, value proposition, or delivery mechanism) while retaining validated learnings.
* **Feedback Prioritization Scoring**:
  $$P = F \times S \times C$$
  *(Where $F$ = Frequency, $S$ = Severity, $C$ = Confidence in evidence)*.
* **PDCA Cycle for Continuous Improvement**: **Plan** $\rightarrow$ **Do** $\rightarrow$ **Check** $\rightarrow$ **Act**.

---

### 3. Product Presentation & Communication Frameworks
* **Audience-Centred Communication**:
  * *Users*: Focus on usability, convenience, and direct benefits.
  * *Engineers*: Focus on technical architecture, feasibility, safety, and component specs.
  * *Investors / Executives*: Focus on market viability, unit economics, scalability, and ROI.
* **High-Impact Presentation Rules**:
  * Start with a compelling user hook or real-world problem evidence.
  * Convey **one clear core message**.
  * Use clean visual slides (one idea per slide, minimal clutter).
  * Show a live or recorded representative user task demo (*"Show, Don't Tell"*).
  * State limitations honestly to establish credibility.

---

### 4. The NABC Model (SRI International)
A powerful 4-part framework for pitching value propositions:
* **N — Need**: What is the critical, validated user pain point?
* **A — Approach**: What is the unique, feasible solution/mechanism?
* **B — Benefits per Costs**: What quantitative and qualitative value is delivered relative to the costs incurred?
* **C — Competition / Alternatives**: How does this outperform existing alternatives, manual workarounds, or non-consumption?

---

### 5. The Elevator Pitch
* **Definition**: A concise 30–60 second pitch delivering maximum clarity under time constraints.
* **Standard Structure**:
  > *"For **[target user]** who experiences **[critical problem]**, our **[product name]** is a **[product category]** that delivers **[key benefit]**. Unlike **[existing alternative]**, our solution **[key differentiator]**. Testing shows **[proven metric/evidence]**."*

---

### 6. Technical Case Study Deliverables
A complete design thinking project portfolio contains:
1. Empathy research findings & Problem Definition (POV / HMW).
2. Divergent ideation artifacts & Concept Selection Matrix.
3. Low and high-fidelity prototypes.
4. User test logs, Feedback Capture Matrices, and iteration history.
5. Final product specifications, system architecture, and viability plan.
