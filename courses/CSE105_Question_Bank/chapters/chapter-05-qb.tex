\section{Technical Viva-Voce Questions \& Conceptual Answers}

\subsection*{Q1. Explain why command 2>\&1 > file does NOT merge streams into the file.}
\begin{vivasol}
The shell processes redirection operators strictly from left to right:
\begin{enumerate}
    \item When the shell encounters \texttt{2>\&1}, descriptor 2 (\texttt{stderr}) is duplicated to point wherever descriptor 1 (\texttt{stdout}) currently points (which is the active display terminal).
    \item Next, when the shell encounters \texttt{> file}, descriptor 1 (\texttt{stdout}) is redirected to point to the file.
\end{enumerate}
As a result, \texttt{stderr} continues pointing to the terminal, and only \texttt{stdout} is redirected into \texttt{file}. The correct order is \texttt{> file 2>\&1}.
\end{vivasol}

\subsection*{Q2. Describe the operational mechanics of an anonymous kernel pipe (|).}
\begin{vivasol}
When the shell executes \texttt{cmd1 | cmd2}, it requests the kernel create an anonymous pipe via the \texttt{pipe()} system call, yielding two file descriptors: a write end and a read end. The shell forks two child processes: the write end is duplicated to \texttt{cmd1}'s stdout, and the read end is duplicated to \texttt{cmd2}'s stdin. Both processes run concurrently. Data flow is buffered in kernel memory (typically 64 KB). If \texttt{cmd1} generates data faster than \texttt{cmd2} consumes it, \texttt{cmd1} is paused by the kernel scheduler until buffer space frees up.
\end{vivasol}
